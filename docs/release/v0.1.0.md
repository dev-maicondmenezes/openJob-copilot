# openJob v0.1.0 — MVP

**Data:** 2026-11-25
**Escopo:** fechamento do MVP (fases F0–F7 do
[plano de release](../plan/release-mvp.md)).

Primeira versão publicável do openJob: copiloto local-first de candidaturas com
feed vertical, currículo adaptado, automação de e-mail/pipeline, IA com BYOK e
distribuição por binário, `.deb` e Docker.

## Destaques

- **Descoberta e feed (CP16):** `/jobs` é a home com feed vertical de tela
  cheia; `/jobs/list` preserva a lista tradicional; detalhe em `/jobs/[id]` com
  Markdown sanitizado.
- **Pipeline por e-mail (CP17):** sincronização Gmail/IMAP, matching em cascata,
  pipeline com 6 colunas, tags `phase:`, sugestões de baixa confiança e
  transições monotônicas.
- **Currículo:** cópia rápida (B10), erros amigáveis no upload/tailoring (B8) e
  exportação em PDF, TXT e MD (B9).
- **IA amigável:** onboarding BYOK (B1), catálogo de presets homologados (B3),
  free tier (B4) e múltiplos perfis com troca do ativo (B2).
- **Backend determinístico (B11):** score BM25, keywords YAKE/RAKE e filtro por
  currículo sem chamadas de LLM, com flags de rollback.
- **Distribuição (CP11):** binário único com SPA embutida, pacote `.deb`,
  imagem Docker multi-arquitetura e release por tag `vX.Y.Z`.
- **Erros de provedor (B6):** catálogo com causa provável + ação, sem expor
  payload, stack ou segredo (`internal/llm/redact.go`).

## Decisões de escopo

- **B7 (LinkedIn OAuth): no-go no MVP.** O escopo OpenID não devolve histórico
  profissional completo; mantido o upload de PDF/MD/TXT.
- **B5 (OAuth de provedores): no-go no MVP.** As APIs OpenAI-compatible não
  emitem token OAuth público para apps pessoais; mantido o fluxo BYOK manual.

Ambas as decisões estão registradas em [`docs/backlog.md`](../backlog.md) e não
bloqueiam o release.

## Instalação

Três caminhos, todos da mesma tag — detalhes em
[`docs/distribution.md`](../distribution.md):

```bash
# binário/.deb
sudo apt install ./openjob_0.1.0_amd64.deb
openjob

# Docker
docker run -d --name openjob -p 8080:8080 -v openjob-data:/data \
  maicondmenezes/openjob:0.1.0

# Docker Compose (imagem publicada)
docker compose up -d
```

## Dados, backup e restore

Banco (`openjob.db`) e master key (`.master.key`) devem ser copiados **juntos**.

- Binário/.deb: `~/.local/share/openjob` (Linux), `~/Library/Application
  Support/openjob` (macOS), `%AppData%\openjob` (Windows).
- Docker: volume `openjob-data` montado em `/data`.
- Restore: pare o app, devolva os dois arquivos e suba de novo. A key restaurada
  com permissão frouxa é corrigida para `600`.
- Sem a master key, as chaves de API cifradas são irrecuperáveis; recadastre-as
  em `/settings`.

## Limitações conhecidas / pendências manuais

- Publicação da imagem Docker e da GitHub Release depende dos secrets
  `DOCKERHUB_USERNAME`/`DOCKERHUB_TOKEN` e da variable `DOCKERHUB_IMAGE`
  (ver [`ci-cd.md`](ci-cd.md)).
- Aceite manual ponta a ponta em celular e desktop (descobrir → pontuar →
  adaptar → candidatar → e-mail → estágio → notificação) é uma etapa humana de
  release; roteiro abaixo.
- CP18/CP19 (usuários/autenticação/OAuth e onboarding gráfico) ficam para
  depois do MVP.

## Checklist de publicação

1. Revisar e mergear a branch de hardening em `main` com os gates verdes.
2. Confirmar ADRs sem colisão (último número usado: `0043`).
3. Confirmar `DOCKERHUB_IMAGE`, `DOCKERHUB_USERNAME` e `DOCKERHUB_TOKEN` no
   repositório.
4. Criar e empurrar a tag anotada `v0.1.0` a partir de `main`:
   `git tag -a v0.1.0 -m "openJob v0.1.0 — MVP" && git push origin v0.1.0`.
5. Acompanhar o workflow `release`: gates → binários/checksums/`.deb` (draft) →
   imagem Docker → release público.
6. Verificar os artefatos: binários (linux/darwin/windows), `checksums.txt`,
   `openjob_0.1.0_amd64.deb`, `openjob_0.1.0_arm64.deb` e a imagem `0.1.0` +
   `latest`.
7. Aceite manual:
   - Celular na mesma rede: abrir o feed, rolar, “Saiba mais”, voltar, buscar.
   - Desktop: descobrir vaga → pontuar → adaptar currículo → candidatar →
     receber e-mail → estágio muda → notificação.
8. Arquivar esta nota na GitHub Release (colar o conteúdo) e comunicar a versão.
